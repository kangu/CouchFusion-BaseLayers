# Remove Umami; analytics always on

## Decision
The built-in engine replaces Umami Cloud entirely. Extending the layer is enough to collect: no
`analytics_mode`, no `umami_*` keys, no required `_config` key at all.

Scope choices (from the user): remove the Umami CSV importer and the `/a.js` Umami compatibility
too; drop `umami_excluded_paths` without a replacement key; leave consuming apps untouched.

## Changes
- **Ingestion:** `server/api/stats.post.ts` always stores locally; nothing is forwarded.
  `stats.options.ts`, `/a.js`, `/l/:slug`, the pixel, share and v1 APIs no longer check a mode.
- **Config:** `server/engine/config.ts` lost `mode`, `storesLocally`, `forwardsToUmami`,
  `excludedPaths` and the `analytics_mode` / `umami_excluded_paths` / `NUXT_PUBLIC_UMAMI_EXCLUDED_PATHS`
  keys. Exclusions now come only from the website record (defaults `/admin*`, `/login`).
- **Startup:** `server/plugins/init.ts` always provisions the databases and website record.
  The aggregator runs whenever `analytics_aggregator_enabled` isn't false.
- **Deleted:** `server/utils/umami-config.ts` (+ spec), the Umami importer and its Tools UI,
  `window.umami` / `data-umami-event` in `/a.js` (use `window.cfa` / `data-cfa-event`),
  `$umami` provide, and the Umami guide docs (`docs/umami-*.md`, `docs/analytics-layer-umami-integration.md`).
- **Client config:** `public.analytics.umami.*` is gone. Live options moved up a level:
  `public.analytics.{includeTitle, sendReferrer, debug, tag}`. `websiteId` and `appName` were
  never used by the server and are no longer sent.
- **Types:** `types/umami.ts` → `types/analytics.ts` (`AnalyticsClient`, `AnalyticsBindingValue`);
  `types/umami.d.ts` → `types/nuxt-app.d.ts` (renamed so it no longer shares a basename with the
  `.ts` file, which made TypeScript skip it).
- **Admin UI:** removed the Mode field, the "analytics is off" gate (SiteGate, Settings) and the
  Umami import option.
- **Docs:** README.md/README.html, agents.md and `docs/self-hosted-analytics.md` updated.

## Deploy impact
- Apps that ran `umami_cloud` start storing locally on deploy and stop sending to Umami Cloud.
  History stays in Umami Cloud; there is no importer for it any more.
- Each consuming app creates `analytics_<slug>` (+ monthly raw databases) in CouchDB on first start.
- Leftover `analytics_mode`, `umami_website_id`, `umami_excluded_paths` keys in `_config` are ignored
  and can be deleted. Any extra exclusions from `umami_excluded_paths` must be re-entered under
  Settings → Website → Excluded paths.
- Apps still contain dead config/markup (not changed, by request): `public.analytics.umami` blocks
  in most `nuxt.config.ts` files, `data-umami-event` in bitvocation/kangu/radustanciu components,
  `window.umami.track` in `apps/radustanciu/app/components/content/Services.vue`. These already did
  nothing before this change (no Umami script is loaded in the Nuxt apps).

## Verification
- Analytics specs: 30 passed, 2 skipped (CouchDB integration). Run with `setupFiles: []` because
  the shared setup needs a local CouchDB, which wasn't running.
- `apps/smart-lead` production build succeeds; the built output contains no Umami code.
- Not verified end to end: storing a hit against a live CouchDB, and the admin pages in a browser.
