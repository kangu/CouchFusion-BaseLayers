# Blink Non-Custodial Provider Implementation Result

## Initial Prompt

Investigate `docs/blink_nc_research.md`, design and implement a full non-custodial Blink Lightning provider named `blink_nc`, use a strict settlement policy, and validate the first integration through Bitvocation.

## Plan Followed

Implemented the committed design and execution plan in `docs/superpowers/`, using test-first provider configuration, bounded LNURL/LUD-21 transport, provider adaptation, public-data isolation, strict CouchDB transitions, reconciliation, expiry ownership, and Bitvocation compatibility checks.

## Implementation Summary

- Added CouchDB-only `blink_nc` configuration with exact `@blink.sv` validation and bounded operational values.
- Added a receive-only LNURL-pay client with HTTPS/host/redirect/timeout/size controls and local mainnet BOLT11 validation.
- Required `SHA256(preimage)` to match the persisted BOLT11 payment hash in both the transport and lifecycle layers.
- Added server-only lookup context, a public response allowlist, deterministic event processing, fulfilment/link/SSE reuse, adaptive reconciliation, restart recovery, final post-grace verification, and protocol-owned expiry.
- Added redacted startup behavior and no webhook route.

## Verification Evidence

- Lightning baseline before feature work: 17 files, 69 tests passed.
- Final Lightning suite during implementation: 26 files, 144 tests passed.
- `git diff --check`: passed at each commit gate.
- Public-boundary route tests cover purchase, donation, and Career Hub responses.
- No live Blink endpoint or mainnet payment was used.

## Known Limitations

- Version 1 is mainnet, receive-only, one Blink address, and one Nitro instance.
- A distributed reconciliation lease is required before multi-instance deployment.
- Bitvocation's consuming-app typecheck is not green at baseline: the repository has no tracked `tsconfig.json`; a temporary standard Nuxt config exposed a large set of pre-existing application/layer errors. Feature-filtered output left only the same missing Node type environment diagnostics for new Node-crypto usage after the feature-specific plugin/config errors were corrected.
- The operator-authorized live payment and restart-recovery smoke test has not been performed.

## Proposed Next Steps

Authorize a capped mainnet smoke test, then add a distributed lease before scaling Nitro horizontally. Separately establish and repair Bitvocation's typecheck baseline.
