# Agent reload guard (Phase 2, Stream C)

## Initial prompt
Phase 2 contract §5 (`cli-init/docs/superpowers/specs/2026-10-30-phase2-workbench-contract.md`): while a CouchFusion Codex generate job runs (marker file at `COUCHFUSION_AGENT_MARKER` exists), stop Vite/Nuxt full-page reloads and HMR caused by create/update/delete of `app/components/content/**` and the generated `app/content-builder/component-definitions.{ts,json}`. Dev only, gated, a strict no-op otherwise. Prove it with a scripted local check.

## Plan followed
1. Baseline: run radustanciu `nuxt dev` on 127.0.0.1:4499 (laptop, local CouchDB), load `/` in a headless dev-browser page, attach a raw Vite HMR WebSocket client (`vite-hmr` subprotocol), then add → edit → delete a probe `ZzStreamCProbe.vue`, logging every broadcast and whether the page reloaded (a token set on `window` survives only without a reload).
2. Trace each message to its sender (`@vitejs/plugin-vue` `handleHotUpdate` → `file-changed`; Vite glob invalidation → `full-reload *`; registry `.ts` propagation → pathless `full-reload`; Vite `prune`; Tailwind CSS `update`) and confirm Vite 7's client `environment.hot` is the same object as `server.ws`.
3. Implement `utils/agent-reload-guard.ts` (pure rules + channel wrapper + Vite plugin) and register it from the existing gated module `utils/register-control-plane-routes.ts` via `vite:extendConfig` (client only) when `nuxt.options.dev && COUCHFUSION_AGENT_MARKER`.
4. Re-run the probe with the marker present (guarded) and absent (control). Unit tests. Clean up.

## Evidence (raw HMR client log, abbreviated)

**Baseline (no guard)** — page reloaded after every step:
- add: `full-reload * …/components/content/ZzStreamCProbe.vue`, `full-reload` + `file-changed component-definitions.ts`, `full-reload` + `file-changed component-definitions.json`
- edit: `file-changed ZzStreamCProbe.vue`, `update css-update:/assets/css/main.css`, then 2× (`full-reload` + `file-changed` registry `.ts`/`.json`)
- delete: `full-reload * …ZzStreamCProbe.vue`, `prune /components/content/ZzStreamCProbe.vue`, `full-reload` + `file-changed` registry `.ts`/`.json`

**Guard installed, marker present** — the client received nothing after `connected`; the page token survived add, edit and delete (no reload). Dev log: 19 messages suppressed (10 `full-reload`, 9 `custom:file-changed`).

**Guard installed, marker absent (control)** — identical to the baseline (same messages, page reloaded each step); no suppression.

## Notes / known gaps
- Pathless `full-reload` and CSS `update` are attributed by a 2.5 s window after a guarded watcher event. An unrelated reload/update that coincides with that window during an agent run is also dropped; the control plane's bridge reload at the end of the job resynchronises the page.
- Stopping `nuxt dev` with a signal skips Nuxt's `close` hook, which leaves the layer's registry watcher (`bun watch-component-registry.mjs`) orphaned. Under systemd (`cf-dev@`, `KillMode=control-group`) the whole group is stopped, so this only matters for ad-hoc local runs.
- The server side of the module graph is still invalidated during the run; only the client notifications are held back.
